# التزامن

يتبع السلطان نموذج Rust في الخيوط والعمليات الذرية والحالة المشتركة (`std::thread`، `std::sync`،
`std::sync::atomic`، `std::sync::mpsc`)، ويتخذ وقت التشغيل في Go مرجعًا لطبقة نظام التشغيل
(بدء الخيط، وfutex، والسيمافور). وقد كُيِّف هذا التصميم مع نظام الملكية في السلطان، وهو نظام بلا
سمات (traits) ولا يشغّل أي مُتلِف (destructor) يكتبه المستخدم. تشرح هذه الصفحة كل بدائية من بدائيات
التزامن، وطبقة نظام التشغيل التي تحتها، والفحص الذي يجري في وقت الترجمة على ما يجوز للخيط أن يلتقطه،
والقيود الحالية. وهي موجهة إلى المبرمجين الذين يتشاركون البيانات بين الخيوط، وإلى من يعملون على
`std.sync`.

## الوحدات

| الوحدة | Rust / Go | المحتوى |

## برنامج أول

عدّاد محمي بقفل، تتشاركه أربعة خيوط عبر `مشترك`، ويزيده كل خيط منها. يملك كل خيط نسخة من `مشترك`،
ولا يُمسك القفل إلا داخل الدالة المغلقة المعطاة إلى `نفذ_مع_القفل`.

```sultan
استورد المكتبة.sync.arc;
استورد المكتبة.sync.mutex;
استورد المكتبة.thread.thread;
استورد المكتبة.تنسيق.fmt;

عرف زد(ق: &متغير ص64): فراغ { *ق := *ق + 1; }
عرف اقرأ(ق: &متغير ص64): ص64 { أرجع *ق; }

عرف أضف_ألفا(ق: &مشترك<قفل<ص64>>): فراغ {
    دع ف: متغير ص64 = 0;
    طالما (ف < 1000) {
        نفذ_مع_القفل(اقرأ_مشترك(ق), دالة(س: &متغير ص64): فراغ -> زد(س));
        ف := ف + 1;
    }
}

عرف الرئيسية(): ص32 {
    دع العداد: مشترك<قفل<ص64>> = أنشئ_مشترك(أنشئ_قفل(0 مثل ص64));
    دع المقابض: متغير متجه مقبض_خيط = [];
    دع خ: متغير ص32 = 0;
    طالما (خ < 4) {
        دع نسختي: مشترك<قفل<ص64>> = استنسخ_مشترك(&العداد);
        طابق أطلق(دالة(): فراغ -> أضف_ألفا(&نسختي)) مع
        | نتيجة.نجح(م) -> { ألحق(المقابض, م); }
        | نتيجة.خطأ(_) -> { أرجع 1; };
        خ := خ + 1;
    }
    دع ض: متغير طبيعي = 0;
    طالما (ض < (الطول(المقابض) مثل طبيعي)) {
        انضم(&متغير المقابض[ض]);
        ض := ض + 1;
    }
    دع المجموع: ص64 = نفذ_مع_القفل(اقرأ_مشترك(&العداد), دالة(س: &متغير ص64): ص64 -> اقرأ(س));
    دع ر: نتيجة طبيعي, خطأ_تنسيق = اطبع_سطرا_منسقا(«المجموع = {}», [قيمة_تنسيق.ص64(المجموع)]);
    أرجع 0;
}
```

يطبع البرنامج المجموع، وهو 4000.

## العمليات الذرية

توفر `std.sync.atomic` أعدادًا صحيحة ذرية (`ذرة_ط64`، و`ذرة_ط32`، و`ذرة_طبيعي`) مع عمليات القراءة،
والكتابة، والتبديل، والمقارنة ثم التبديل (compare-exchange)، والجلب مع الجمع (fetch-add)، وسياجًا
للذاكرة. ولـ `ذرة_ط64` أيضًا الجلب مع «و» البتية والجلب مع «أو» البتية، وله صيغ بمؤشر تأخذ خلية
`*متغير`. وتتبع ترتيبات الذاكرة النوع `Ordering` في Rust:

| بالإنجليزية | بالعربية |
|---|---|
| `memory_ordering.relaxed` | `ترتيب_ذاكرة.مسترخ` |
| `memory_ordering.release` | `ترتيب_ذاكرة.إطلاق` |
| `memory_ordering.acquire` | `ترتيب_ذاكرة.اكتساب` |
| `memory_ordering.acq_rel` | `ترتيب_ذاكرة.اكتساب_وإطلاق` |
| `memory_ordering.seq_cst` | `ترتيب_ذاكرة.تسلسلي` |

هذه العمليات دوال جوهرية في المترجم (intrinsics): `بدائي_ذري_حمل`، و`بدائي_ذري_خزن`، و`بدائي_ذري_تبديل`،
و`بدائي_ذري_قارن_وبدل`، و`بدائي_ذري_جلب_جمع`، والعمليات البتية `بدائي_ذري_جلب_و` و`بدائي_ذري_جلب_أو`
و`بدائي_ذري_جلب_أو_حصري` (الجلب مع «أو» الحصرية)، و`بدائي_سياج_ذاكرة` (السياج). وهي، على خلاف كل
عملية أخرى، تقرأ العدد الصحيح الذي يشير إليه مرجع مشترك وتكتب فيه. وهذه هي النقطة السليمة الوحيدة
للتعديل من خلال مرجع مشترك (interior mutability)، كما في Rust حيث تأخذ العمليات الذرية `&self`. وتقبل
الواجهة الأمامية للمترجم مرجعًا مشتركًا `&` إلى عدد صحيح من 32 بتًا أو 64 بتًا أو بحجم المؤشر بوصفه
المعامل الأول.

تخفض كل خلفية هذه الدوال الجوهرية إلى التعليمات الذرية للمعمارية بقوة الاتساق التسلسلي (sequential consistency).
ويُمرَّر الترتيب المطلوب إلى الخلفية، لكن الخلفيات تعامل كل ترتيب على أنه `ترتيب_ذاكرة.تسلسلي`، وهذا
سليم دائمًا.

| الخلفية | الخفض |
|---|---|
| x86_64 (الأصلية وLLVM) | `LOCK XADD`، و`XCHG`، و`LOCK CMPXCHG` (والعمليات البتية «و» و«أو» و«أو» الحصرية في صورة حلقة `CMPXCHG`)، و`MFENCE` |
| arm64 (LLVM؛ والخلفية الأصلية على Darwin) | صيغ ARMv8.1 LSE: `LDADDAL`، و`SWPAL`، و`LDCLRAL`، و`LDSETAL`، و`LDEORAL`، و`CASAL`، و`LDAR`، و`STLR`، و`DMB ISH` |
| wasm32 | قراءات وكتابات عادية في الذاكرة الخطية: فوحدة wasm32 تعمل بخيط واحد (لا تُستخدم خيوط WASI)؛ والسياج لا يفعل شيئًا |
| LLVM | `atomicrmw`، و`cmpxchg`، و`fence` بالترتيب `seq_cst` |
| المفسر | خيط نظام تشغيل واحد، فالعملية الذرية هي قراءة وتعديل وكتابة عادية للخلية التي يسميها المرجع؛ وتُنفَّذ الكتابة حتى لو كان المرجع مشتركًا (`compiler/interpreter/execution/primitives.sn`) |

## خيوط نظام التشغيل

توفر `std.thread` ما يلي:

| بالإنجليزية | بالعربية | Rust |
|---|---|---|
| `spawn` | `أطلق` | `thread::spawn`: تنقل دالة مغلقة إلى خيط جديد وتعيد مقبض انضمام |
| `join` | `انضم` | `JoinHandle::join` |
| `spawn_value`, `join_value` | `أطلق_بقيمة`, `انضم_بقيمة` | خيط تعيد فيه الدالة المغلقة قيمة، وتعيدها `انضم_بقيمة` في صورة `اختياري` |
| `sleep` | `نم` | `thread::sleep` (بالثواني والنانوثواني) |
| `yield_now` | `تنازل` | `thread::yield_now` |
| `current_id`, `join_handle_id` | `معرف_الخيط_الحالي`, `معرف_المقبض` | معرّف الخيط في نظام التشغيل |
| `available_parallelism` | `عدد_المعالجات_المتاحة` | `thread::available_parallelism` |

تعيد `أطلق` قيمة `نتيجة` خطؤها هو إخفاق المنصة في بدء خيط.

### دعم المنصات

في `std.os.threads` فرع محروس واحد لكل نظام تشغيل. ويبدأ كل نظام الخيط بالآلية التي يستخدمها وقت
التشغيل الخاص به.

| نظام التشغيل | البدء | الانضمام |
|---|---|---|
| Linux وAndroid (كل المعماريات) | `clone` على مكدس تحجزه المكتبة القياسية، باستدعاءات نظام مباشرة دون libc | انتظار futex على خلية tid التي تصفّرها النواة عند خروج الخيط |
| FreeBSD | `thr_new` على مكدس تحجزه المكتبة القياسية | انتظار `_umtx_op` على كلمة الحالة الخاصة بـ `thr_exit` |
| macOS | `pthread_create` | `pthread_join` |
| Windows | `CreateThread` | `WaitForSingleObject`، و`GetExitCodeThread`، و`CloseHandle` |
| WASI، والأهداف المستقلة عن نظام التشغيل (freestanding)، والمفسر | غير مدعوم: تعيد `أطلق` خطأً | |

### طبقة الخيوط في Linux

تبدأ طبقة Linux (`library/std/os/platform/unix/linux/threads.sn`) الخيط بالطريقة التي يتبعها وقت
التشغيل في Go وmusl. فيحصل الخيط على مكدس حجمه 2 MiB محجوز بـ `mmap` مع صفحة حماية `PROT_NONE`، ويُستدعى له
`clone` بالأعلام `CLONE_VM|FS|FILES|SIGHAND|THREAD|SYSVSEM|PARENT_SETTID|CHILD_CLEARTID`. واستدعاء
`clone` هو دالة المترجم الجوهرية `بدائي_استنسخ_خيط_نواة`: يشغّل الخيط الابن الدالة المغلقة على
المكدس الجديد ثم ينهي الخيط. وتنتظر `انضم` على خلية tid التي تصفّرها النواة حين يخرج الخيط.

ويختلف تفصيلان بين المعماريات. توضع خلية tid في كلتا الخانتين الأخيرتين من وسائط `clone`، لأنهما
(child_tid, tls) على x86_64 و(tls, child_tid) على المعماريات asm-generic (aarch64، وriscv64،
وloongarch64)؛ وتُتجاهل خانة tls من دون `CLONE_SETTLS`. وتفحص `انضم` الكلمة كاملة، لأن tid النواة،
وهو من 32 بتًا، يقع في النصف الأعلى على الأجهزة التي تضع البايت الأعلى أولًا (big-endian) مثل s390x
وsparc64.

وحجز المكدس مشترك مع طبقة FreeBSD: فـ `mmap` و`mprotect` و`munmap` تأخذ الوسائط نفسها هناك، وتأتي
الأعلام من UAPI النواة المختارة.

### ملكية الدالة المغلقة

يملك الخيط دالته المغلقة، كما تُنقل `FnOnce` في Rust إلى الخيط. وتوضع الدالة المغلقة في خلية على
الكومة تملكها دالة الدخول المغلقة الخاصة بالخيط. وتُخرج دالة الدخول الدالة المغلقة بالتبديل، وتشغّلها،
وتتلفها حين تعود، فيُحرَّر كل ما التقطته الدالة المغلقة (نسخة من `مشترك`، أو مرسل قناة) عند انتهاء
الخيط، لا عند الانضمام إليه ولا بحسب حدوث الانضمام. وتعيد `انضم` آخر مرجع لدالة الدخول، بعد بنائه من عنوانه
بـ `بدائي_دالة_من_عنوان`، فتُحرَّر دالة الدخول وخليتها. أما الخيط المنفصل (detached) فلا يسرّب إلا دالة الدخول
(كتلتين صغيرتين).

### النتائج والانهيار

الدالة المغلقة المعطاة إلى `أطلق` لا تعيد قيمة عبر `انضم`؛ أما `أطلق_بقيمة` و`انضم_بقيمة` فتعيدان
القيمة عبر حالة مشتركة. و`إنهيار` في أي خيط ينهي العملية (process) كلها (panic=abort)، فلا ترى `انضم` أبدًا
خطأ خيط، ولا يمكن أن يُعلَّم قفل بأنه معطوب بسبب انهيار حدث وهو ممسوك (poisoning).

## الانتظار والإيقاظ

`std.os.wait_address` هي بدائية الحجب الوحيدة التي تُبنى عليها كل أنواع `std.sync`، على غرار
`sys/sync/futex` في Rust و`runtime/sema` في Go.

| الاستدعاء | المعنى |
|---|---|
| `انتظر_عند_العنوان(&ذرة_ط32, المتوقعة, المهلة)` | النوم ما دامت الخلية تحمل `المتوقعة`؛ ولا تعيد `خطأ` إلا حين تكون المهلة النسبية (بالنانوثواني، أو بلا مهلة) قد انقضت |
| `أيقظ_واحدا_عند_العنوان`، `أيقظ_الكل_عند_العنوان` | إيقاظ نائم واحد أو كل النائمين على الخلية |
| `انتظر_عند_الخلية`، `أيقظ_واحدا_عند_الخلية` | الشيء نفسه على خلية مجردة من 32 بتًا، مثل متغير وحدة عددي يُستخدم كلمةَ قفل |
| `هل_الانتظار_عند_العنوان_مدعوم` | هل للهدف انتظار حاجب |

فحص القيمة والنوم خطوة واحدة في النواة، فلا يضيع أبدًا إيقاظ يقع بين قراءة المستدعي وانتظاره. وقد
يعود الانتظار دون سبب (spuriously)، ولذلك يعيد المستدعون فحص شرطهم في حلقة.

| نظام التشغيل | الانتظار | الإيقاظ | ملاحظات |
|---|---|---|---|
| Linux وAndroid | `futex(FUTEX_WAIT_PRIVATE)` | `futex(FUTEX_WAKE_PRIVATE)` | تستخدم الانتظارات ذات المهلة `futex_time64` على i686 وarmv7 (`مستقبل_بمهلة`)، فيكون `timespec` من 64 بتًا في كل مكان؛ وقيمة `ETIMEDOUT` هي 110 (و145 على mips، و60 على sparc) |
| FreeBSD | `_umtx_op(UMTX_OP_WAIT_UINT_PRIVATE)` | `_umtx_op(UMTX_OP_WAKE_PRIVATE)` | المهلة قيمة `struct timespec` نسبية تُمرَّر في `uaddr2` (`مستقبل_بمهلة_بي_إس_دي`) |
| macOS | `__ulock_wait2(UL_COMPARE_AND_WAIT \| ULF_NO_ERRNO)` | `__ulock_wake` (`ULF_WAKE_ALL`) | ما يستخدمه Rust قبل macOS 14.4؛ و`os_sync_wait_on_address` غير موجودة في حزمة التطوير (SDK) 11.3. وتُستورد من libSystem ويفحصها `tools/audit/macos_imports_audit.py` |
| Windows | `WaitOnAddress` | `WakeByAddressSingle` / `WakeByAddressAll` | `api-ms-win-core-synch-l1-2-0.dll`، وهو استيراد `synchronization` في Rust؛ و`ERROR_TIMEOUT` يدل على انقضاء المهلة |
| WASI، والأهداف المستقلة | تعود فورًا (والانتظار ذو المهلة يبلّغ عن انقضائها) | لا شيء | خيط واحد: فلا أحد يستطيع تغيير الخلية |

وتحمل استدعاءات النواة عقودًا للذاكرة (`توقيع_عملية_نواة_لينكس`: الخلية ذات 4 بايتات، و`timespec` ذو
16 بايتًا)، كما يحملها كل استدعاء نواة في المكتبة القياسية يأخذ مؤشرًا.

## الملكية المشتركة

`مشترك<ق>` هو `Arc<T>` في Rust: قيمة واحدة على الكومة، وأي عدد من المقابض، وعدّاد مراجع ذري،
وتُتلَف القيمة مرة واحدة بالضبط مع آخر مقبض.

لا يشغّل السلطان أي مُتلِف يكتبه المستخدم، ولذلك فالعدّاد والإتلاف من شأن بيئة دالة مغلقة. يحمل
المقبض دالة مغلقة واحدة تملك بيئتُها القيمةَ المغلفة في صندوق (التقاط بالنقل). وعدّاد المراجع في البيئة هو
العدّاد القوي: تعدّ الدوال المغلقة مراجعها ذريًا (`LOCK XADD`، و`LDADDAL`، و`atomicrmw` في LLVM)،
ونسخ المقبض يضيف مرجعًا، وإتلافه يزيل مرجعًا، ويتلف مُتلِف البيئة الصندوقَ مع آخر مرجع. وتعيد
الدالة المغلقة عنوان القيمة المغلفة.

| بالإنجليزية | بالعربية | Rust |
|---|---|---|
| `arc_new` | `أنشئ_مشترك` | `Arc::new` |
| `arc_clone` | `استنسخ_مشترك` | `Arc::clone`؛ ونسخ المقبض هو الاستنساخ نفسه، لأن الدوال المغلقة قيم قابلة للنسخ |
| `arc_get` | `اقرأ_مشترك` | `Deref`: مرجع مشترك |
| `arc_strong_count` | `عدد_مراجع_مشترك` | `Arc::strong_count`؛ تقرأ خانة العدّاد في البيئة |
| `arc_ptr_eq` | `هل_المشترك_نفسه` | `Arc::ptr_eq` |
| `arc_as_ptr` | `مؤشر_مشترك` | `Arc::as_ptr` |

لا يُوصَل إلى القيمة إلا عبر مرجع مشترك. والتعديل عبر الخيوط يمر بقفل، أو بقفل قراءة وكتابة، أو
بعدد ذري داخل `مشترك`. ولا يعدّ المفسر مراجع الدوال المغلقة، فلا يُحرَّر `مشترك` فيه أبدًا،
و`عدد_مراجع_مشترك` غير متاحة فيه (إذ تُرفض الدوال الجوهرية الخاصة بعناوين الدوال المغلقة).

## القفل

`قفل<ق>` هو قفل futex في Rust (`sys/sync/mutex/futex.rs`، المبني على ورقة Ulrich Drepper
"Futexes Are Tricky"). والحالة 0 حين يكون مفتوحًا، و1 حين يكون مقفلًا، و2 حين يكون مقفلًا وله منتظرون.
وأخذ القفل دون تنافس عملية مقارنة وتبديل واحدة، وفتحه دون تنافس عملية تبديل واحدة، ولا يحتاج أي منهما إلى استدعاء نظام.
أما أخذ القفل مع التنافس فيدور (spin) 100 جولة، ثم يجعل الحالة 2 وينام؛ وفتح القفل الذي يجد الحالة 2 يوقظ
نائمًا واحدًا.

لا يُوصَل إلى القيمة إلا داخل دالة مغلقة تعمل والقفل ممسوك: `نفذ_مع_القفل(&م, دالة(&متغير ق): ن): ن`،
أو `حاول_القفل`، التي تعيد `اختياري.لا_شيء` حين يمسك خيط آخر القفل. وهذا هو `MutexGuard` في Rust
محصورًا في استدعاء واحد، لأن السلطان لا يشغّل شيئًا عند الخروج من النطاق: فلا يمكن نسيان فتح القفل،
ولا يعيش مرجع إلى القيمة بعد القفل. وتبلّغ `هل_القفل_مأخوذ` عن الحالة.

ولا يُعلَّم القفل بأنه معطوب أبدًا، لأن الانهيار ينهي العملية. والقفل يُنقل لكنه لا يُنسخ أبدًا
(إذ تجعله علامةٌ هي متجه لم يُخصَّص له مخزن قط قيمةً مملوكة)، ويُتشارك عبر `مشترك` (`مشترك<قفل<ق>>`)، كما في Rust.

## قفل القراءة والكتابة

`قفل_قراءة_كتابة<ق>` كلمة futex واحدة: 0 حين يكون حرًّا، وعدد القرّاء حين يكون فيه قرّاء، و`0xFFFFFFFF` حين يكون فيه كاتب.
ويكون الوصول عبر `نفذ_مع_قراءة` و`نفذ_مع_كتابة`. وهو أبسط من قفل القراءة والكتابة المبني على futex
في Rust (`RwLock`): فلا أولوية فيه للكاتب، وقد يؤخر تدفق متواصل من القرّاء الكاتبَ.

## شرط الانتظار

`شرط_انتظار` هو متغير الشرط المبني على futex في Rust (`Condvar`): رقم تسلسل من 32 بتًا. تقرأ
`انتظر_الشرط(&ش, &م)` الرقم، وتفتح القفل، وتنام ما دام الرقم لم يتغير، ثم تأخذ القفل من جديد. ويزيد
التنبيه الرقم ويوقظ نائمًا واحدًا (`نبه_واحدا`) أو الجميع (`نبه_الكل`).

يُستدعى الانتظار والقفل ممسوك، داخل الدالة المغلقة المعطاة إلى `نفذ_مع_القفل` على القفل نفسه. ويبقى
مرجع الدالة المغلقة إلى القيمة صالحًا، لأن القفل يكون ممسوكًا من جديد حين يعود الانتظار. وتعيد
`انتظر_الشرط_بمهلة` ما إذا كانت مهلة الانتظار قد انقضت؛ وتكرر `انتظر_طالما` الانتظار في حلقة بحسب شرط على القيمة
المحمية.

## التهيئة لمرة واحدة

`مرة` هو `Once` المبني على futex في Rust: 0 غير مكتمل، و1 قيد التشغيل، و2 قيد التشغيل وله نائمون،
و3 مكتمل. تشغّل `نفذ_مرة` دالتها المغلقة مرة واحدة بالضبط مهما كان عدد الخيوط المتسابقة، وتنام الخيوط الأخرى حتى
يكتمل التشغيل. و`مرة` المكتملة كلفتها قراءة واحدة بترتيب الاكتساب.

تخزن `خلية_مرة<ق>` (`OnceLock` في Rust) قيمتها في متجه لا يتجاوز عنصرًا واحدًا، موضوع خلف `مشترك`. والعنصر
موضع في الذاكرة، فتعيره `اقرأ_خلية_مرة` و`اقرأ_أو_هيئ_خلية_مرة` في مكانه، ولا يكبر المتجه أبدًا بعد
الإلحاق الوحيد، فيبقى عنوانه ثابتًا. وترفض `اضبط_خلية_مرة` قيمة ثانية.

## القنوات

تعيد `قناة<ق>()` و`قناة_متزامنة<ق>(الحد)` الطرفين كليهما (`طرفا_قناة`)، ويفككهما نمط:
`| { المرسل: م, المستلم: س } -> …`. وتنشئ `مستلم_قناة` و`مرسل_لمستلم` الطرفين واحدًا بعد الآخر.
وللقناة مرسلون كثيرون (`استنسخ_مرسل`) ومستلم واحد، وهي تسلّم قيم كل مرسل بالترتيب الذي أُرسلت به (FIFO).

| العملية | بالإنجليزية | بالعربية |
|---|---|---|
| الإرسال، مع انتظار مكان في قناة محدودة | `send` | `أرسل` |
| الإرسال دون انتظار | `try_send` | `حاول_الإرسال` |
| الاستقبال، مع الانتظار | `recv` | `استقبل` |
| الاستقبال دون انتظار | `try_recv` | `حاول_الاستقبال` |
| الاستقبال بمهلة | `recv_timeout` | `استقبل_بمهلة` |
| إتلاف طرف صراحةً | `drop_sender`, `drop_receiver` | `أسقط_مرسل`, `أسقط_مستلم` |

تعيد `أرسل` القيمة بوصفها الخطأ حين يكون المستلم قد زال. وتبلّغ `حاول_الإرسال` عن `ممتلئة` أو `منقطعة`، مع
القيمة. وتفشل `استقبل` حين يكون كل المرسلين قد زالوا ولم يبقَ شيء في الطابور. وتبلّغ `حاول_الاستقبال`
و`استقبل_بمهلة` عن الفراغ، أو انقضاء المهلة، أو الانقطاع، مستخدمةً أنواع الأخطاء الخاصة بـ `mpsc` في
Rust (`خطأ_محاولة_استقبال`، و`خطأ_استقبال_بمهلة`، و`خطأ_استقبال`، و`خطأ_محاولة_إرسال`).

### التنفيذ

تقع الحالة المشتركة خلف `مشترك`، وهي طابور من متجهين: تُلحق القيم بالمتجه الوارد (inbox)، وتُسحب من المتجه الصادر (outbox)
الذي يُعاد ملؤه من الوارد، فكل قيمة تُنقل ولا تُنسخ أبدًا. ويحمي الطابورَ القفلُ ذو الحالات الثلاث، وترافقه
كلمتا تسلسل futex: "قيمة متاحة" و"خانة فارغة".

### الانقطاع دون مُتلِفات

تعدّ القناة طرفيها برمزين مشتركين (من نوع `مشترك`). كل رمز تحمله الحالة المشتركة ويحمله كل مرسل (أو
المستلم)، فعدد المرسلين الأحياء هو العدّاد القوي لرمز المرسل ناقصًا المرجعَ الذي تحمله الحالة نفسها. والطرف
المعطى إلى `أسقط_مرسل` أو `أسقط_مستلم` يُتلف هناك، ويُوقَظ الطرف الآخر فورًا. أما الطرف الذي يُتلف
ضمنيًا، بانتهاء خيط أو انتهاء نطاق، فيلاحظه الخيط المنتظر خلال بضع ميلي ثوانٍ، لأن المنتظر يعيد فحص
العدّادات بين فترات نوم محدودة (1 ms تتضاعف حتى 32 ms). والأطراف غير قابلة للنسخ، فالدالة المغلقة
المُطلقة في خيط تنقل الطرف الذي تلتقطه.

الحد 0 يحمل قيمة واحدة، أي أن قناة rendezvous في Rust غير منفذة.

## الخلو من سباق البيانات: فحص الالتقاط عند الإطلاق

لا يجوز للدالة المغلقة المسلَّمة إلى خيط آخر أن تلتقط إلا ما يجوز نقله بين الخيوط، وهذا ما يعبّر عنه القيد
`F: Send + 'static` في Rust. ويرفض المترجم الدالة المغلقة التي تلتقط:

- مؤشرًا خامًا، إلا إذا وقع الإطلاق داخل `غير_آمن`؛
- مرجعًا مستعارًا أو شريحة؛
- متغير وحدة قابلًا للكتابة يستخدمه جسمها خارج كتلة غير آمنة.

ولكل حالة رسالة تشخيص خاصة بها، بالعربية والإنجليزية: `SULTANC-THREAD-CAPTURE-RAW-POINTER`،
و`SULTANC-THREAD-CAPTURE-REFERENCE`، و`SULTANC-THREAD-CAPTURE-NON-ATOMIC-SHARED`. وتُستنتج الاستدعاءات
التي ترسل دالة مغلقة من الدوال الجوهرية الخاصة بعناوين الدوال المغلقة، لا من قائمة بالأسماء. والقواعد،
وطريقة الاستنتاج، وحدودهما مشروحة في [نظام الأنواع](type-system.md#قواعد-الالتقاط-في-الخيوط).

وتبقى الدوال الجوهرية الخاصة بالخيوط نفسها خلف `غير_آمن`: فـ `بدائي_استنسخ_خيط_نواة` تشغّل شيفرة على
مكدس يقدمه المستدعي، و`بدائي_دالة_من_عنوان` تعيد بناء دالة مغلقة من عنوان. وتسريب صندوق
(`بدائي_سرب_قيمة`) دالة جوهرية غير آمنة كذلك.

## الحالة على مستوى العملية

جُعل جدولان على مستوى العملية آمنين للاستعمال مع الخيوط.

- يخدم مخصِّص الذاكرة (`library/std/os/allocation.sn`) كل الخيوط. ويضبط أول إطلاق علمًا يفعّل قفلًا حول
  التخصيص وإعادة التخصيص والتحرير؛ والبرنامج الذي لا يطلق خيطًا أبدًا لا يدفع إلا كلفة تفرع واحد. وتكشف
  `هل_بدأت_خيوط` هذا العلم. والقفل هو بروتوكول futex ذو الحالات الثلاث الخاص بـ `قفل`، مطبقًا على كلمة وحدة
  من 32 بتًا: عملية مقارنة وتبديل واحدة حين يكون حرًّا، و100 دورة على الأكثر حين يكون ممسوكًا، ثم نوم
  في النواة (`os.platform.*.wait_address`، الاستدعاءات بلا مهلة، وهي لا تخصص ذاكرة)، فلا يستهلك
  الخيط المنتظر وقت المعالج. ومع ذلك تتشارك كل الخيوط هذا القفل الواحد؛ ولو وُجدت ذاكرة مؤقتة (cache) لكل خيط
  لأزالت القفل من أغلب عمليات التخصيص.
- يأخذ جدول البيئة (`std.env.table`؛ ويقابله `ENV_LOCK` في Rust و`envLock` في Go) قفلًا واحدًا على مستوى
  العملية لكل قراءة وكتابة بمجرد وجود خيط، مستخدمًا البروتوكول ذا الحالات الثلاث على متغير وحدة عددي
  (`انتظر_عند_الخلية`). وقبل أول خيط لا يؤخذ أي قفل.

## استطلاع الجاهزية

تتيح `std.os.poll` (على غرار mio في Rust وnetpoller في Go) لخيط واحد أن يخدم مقابس كثيرة غير حاجبة:
epoll على Linux وAndroid، وkqueue على FreeBSD (باستدعاءات النظام) وmacOS (عبر libSystem). وفي
Windows والأهداف الأخرى تعيد `هل_المستطلع_مدعوم` القيمة خطأ؛ فـ Windows تحتاج إلى IOCP، وهو نموذج قائم على الإكمال (completion).

| الاستدعاء | mio / epoll |
|---|---|
| `أنشئ_مستطلع` | `Poll::new`؛ `epoll_create1(EPOLL_CLOEXEC)`، `kqueue()` |
| `سجل_في_مستطلع` | `Registry::register`؛ `EPOLL_CTL_ADD`، `EV_ADD` |
| `أعد_تسليح_في_مستطلع` | `Registry::reregister`؛ `EPOLL_CTL_MOD`، `EV_ADD` |
| `ألغ_من_مستطلع` | `Registry::deregister`؛ `EPOLL_CTL_DEL`، `EV_DELETE` |
| `انتظر_مستطلع` | `Poll::poll`؛ `epoll_pwait`، `kevent` |
| `حدث_مستطلع_عند` | `Events::iter`: الرمز، وقابلية القراءة، وقابلية الكتابة، والإغلاق من الطرف الآخر، أو الخطأ |

التسجيلات من نوع المرة الواحدة (`EPOLLONESHOT`، `EV_ONESHOT`): يعطّل الحدثُ واصفه حتى يُعاد تسليحه، فتستطيع
خيوط عدة أن تنتظر على مستطلع واحد، ويصل كل واصف إلى واحد منها في كل مرة. والاهتمام إما بالقراءة أو
بالكتابة، لا بهما معًا، للسبب نفسه (فقد ينطلق مرشحان من kqueue على خيطين). ويملك كل خيط منتظر مخزن
أحداثه (`أنشئ_مخزن_أحداث_مستطلع`)، فلا يخصص الانتظار ذاكرة. وتتعرف `هل_خطأ_سيحظر` على خطأ «العملية
ستحجب» (would-block) الخاص بالهدف.

وتُبنى عليها `شغل_خادم_ويب_بأحداث` في `std.http.server`: تتشارك خيوط عاملة (عددها الافتراضي هو
التوازي المتاح) مستطلعًا واحدًا، ويسلّم الحدث اتصالًا إلى عامل واحد، فيقرأ حتى يصير المقبس على وشك
الحجب، ويشغّل المعالج لكل طلب HTTP/1 مكتمل، ويكتب دون حجب (ينتظر الخرج غير المرسل قابلية الكتابة)،
ثم يعيد تسليح الاتصال. ولا تحتجز الاتصالات الخاملة أي خيط. وتُتشارك الحالة في صورة `مشترك<S>`.
ويغادر اتصال h2c المستطلع إلى خادم HTTP/2 الحاجب على عامله؛ وما زال HTTPS يستخدم
`شغل_خادم_ويب_آمن` التسلسلية. وحين لا يتوفر مستطلع، تشغّل هذه الدالة `شغل_خادم_ويب`.

## المفسر

يعمل `sultanc run` على خيط واحد من خيوط نظام التشغيل. فتعمل العمليات الذرية في صورة قراءة وتعديل
وكتابة عادية، ويعمل `قفل`، و`قفل_قراءة_كتابة`، و`شرط_انتظار` (التنبيه)، و`مرة`،
و`خلية_مرة`، وقراءات `مشترك`، وتتفق نتائجها مع الشيفرة الأصلية؛ والاختبار `tests/*/stdlib/behavior/sync_single_thread.sn`
زوج اختبار تفاضلي. ويُبلَّغ عن `بدائي_استنسخ_خيط_نواة` والدوال الجوهرية الخاصة بعناوين الدوال المغلقة بأنها
بدائيات آلة غير مدعومة، فلا يتاح هناك إطلاق الخيوط، ولا `عدد_مراجع_مشترك`، ولا القنوات (التي تعدّ
أطرافها بهذه الدالة).

## القيود

- لا يرى فحص الالتقاط عند الإطلاق ما وراء دالة مغلقة ممررة في متغير، أو دالة مغلقة ملتقطة، أو
  استدعاء يلمس متغير وحدة قابلًا للكتابة. ويتتبع Rust هذه الحالات بالسمات التلقائية (auto traits) على
  أنواع الدوال المغلقة.
- تحتاج الخيوط ذات النطاق (`thread::scope`) إلى دعم للمناطق وأعمار المراجع لا يعبّر عنه فاحص الملكية
  بكلفة منخفضة. ولا توجد متغيرات محلية للخيط (thread-locals)، ولا حواجز (barriers)، ولا `WaitGroup`.
- تتجاهل العمليات الذرية الترتيبات الأضعف وتستخدم `ترتيب_ذاكرة.تسلسلي` دائمًا.
- لا أولوية للكاتب في قفل القراءة والكتابة.
- تلاحظ القنوات الطرف المُتلَف ضمنيًا بالاستطلاع الدوري، في غضون 32 ms.
- تخدم `شغل_خادم_ويب` و`شغل_خادم_ويب_آمن` اتصالًا واحدًا في كل مرة؛ وتخدم `شغل_خادم_ويب_بأحداث`
  المبنية على الأحداث طلبات HTTP/1 بالتزامن، لكن اتصال h2c يحتجز عامله، وTLS ليس مبنيًا على الأحداث بعد،
  ولا مستطلع في Windows (IOCP).
- الخيوط غير متاحة على WASI، ولا على الأهداف المستقلة عن نظام التشغيل، ولا في المفسر.
