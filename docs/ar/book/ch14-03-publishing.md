# نشر حزمة

حين تكون مكتبتك مفيدة لغيرك، انشرها في فهرس الحزم، فيضيفها أي أحد بـ `supax add`.

## قبل النشر

تُنشر الحزمة حين:

- يكون فيها قسم `[lib]`: فالفهرس يحفظ مكتبات تستوردها الحزم الأخرى؛
- ويتبع إصدارها الإصدار الدلالي: `MAJOR.MINOR.PATCH`، مثل `0.2.0`؛
- ولا يكون فيها اعتماديات `path`، فلا أحد غيرك يملك مجلداتك؛
- وتكون شيفرتها محفوظة في مستودع git عام، دون تغييرات غير محفوظة.

واختر الإصدار بحسب ما تغيّر. زد `PATCH` للإصلاحات، و `MINOR` للميزات الجديدة التي لا تكسر الشيفرة الموجودة، و `MAJOR` حين قد
تتوقف عن الترجمة شيفرة استخدمت الإصدار السابق. والإصدارات تحت 1.0.0 للحزم التي ما زالت تبحث عن شكلها.

## تجهيز المُدخل

يفحص `supax package` كل ما سبق للـ commit الذي أنت عليه، ويحسب بصمة محتواه، ويطبع المُدخل الخاص بالفهرس، مع مسار الملف الذي
ينتمي إليه:

```console
$ supax package --git https://github.com/you/greeting
```

والنشر بعدها تغيير في مستودع الفهرس: أضف المُدخل المطبوع إلى ملف الحزمة، وافتح pull request على
`https://github.com/sultan-language/index`. وحين يُدمج يعمل `supax add` للجميع.

والإصدار المنشور لا يتغير أبدا، فلإصلاح خطأ انشر إصدارا جديدا.

## الخلاصة

- تأتي الاعتماديات من مجلد (`path`)، أو الفهرس (متطلب إصدار)، أو git (وسم).
- يديرها `supax add` و `remove` و `tree` و `update`، وتُستورد وحدات الاعتمادية باسم حزمتها.
- يسجل `Supax.lock` الـ commit والبصمة الدقيقين لكل اعتمادية، فاحفظه في git.
- تجعل `--offline` و `--locked` و `--frozen` البناء قابلا للتكرار، ويفحص `supax verify` المخبأ.
- يجهّز `supax package` إصدارا للفهرس.
