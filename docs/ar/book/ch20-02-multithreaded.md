# خادم متعدد الخيوط

## مشكلة الخيط الواحد

يعالج الخادم اتصالا واحدا في كل مرة. فما دام يعمل على واحد، ينتظر كل متصفح آخر. ولترى ذلك أضف صفحة بطيئة عمدا: `/sleep` تنتظر
خمس ثوان قبل أن تجيب. أضف `استورد المكتبة.وقت.الوقت;` وفرعا لاختيار الصفحة:

<sub>القائمة 20-2: صفحة بطيئة. الملف: src/main.sn</sub>

```sultan ignore
    إذا (سطر_الطلب == "GET / HTTP/1.1") {
        الحالة := "HTTP/1.1 200 OK";
        اسم_الملف := "hello.html";
    } وإلا إذا (سطر_الطلب == "GET /sleep HTTP/1.1") {
        طابق نم_نانو(5000000000) مع
        | نتيجة.نجح(_) -> { }
        | نتيجة.خطأ(_) -> { };
        الحالة := "HTTP/1.1 200 OK";
        اسم_الملف := "hello.html";
    } وإلا {
        الحالة := "HTTP/1.1 404 NOT FOUND";
        اسم_الملف := "404.html";
    };
```

اطلب `/sleep`، وبينما ينتظر اطلب `/` من طرفية أخرى:

```console
$ curl -s -o /dev/null http://127.0.0.1:7878/sleep &
$ time curl -s -o /dev/null http://127.0.0.1:7878/
```

فيستغرق الطلب الثاني، الذي لا ينبغي أن يستغرق شيئا، خمس ثوان: إنه ينتظر خلف الأول. والخادم الحقيقي، بآلاف الزوار، لا يعمل هكذا.

## مجموعة عمال

الحل أن يعمل على عدة اتصالات معا، كل منها في خيط. وبدء خيط جديد لكل اتصال سيعمل، لكن هجوما يفتح آلاف الاتصالات سيبدأ آلاف
الخيوط. فبدلا من ذلك يبدأ الخادم عددا ثابتا من الخيوط مرة واحدة، *مجموعة خيوط* (thread pool)، ويسلّم كل اتصال لواحد منها.

وكيف يصل الاتصال إلى عامل؟ عبر قناة، من الفصل الخامس عشر. فكل عامل يملك طرف الاستلام لقناته، وينتظر عليه، وتحتفظ `الرئيسية`
بالمرسلين، وترسل كل اتصال جديد إلى العامل التالي بالدور. والإرسال ينقل التدفق إلى القناة، والاستلام ينقله منها إلى العامل،
فلا يملك كل اتصال في أي لحظة إلا خيط واحد.

<sub>القائمة 20-3: العمال. الملف: src/main.sn</sub>

```sultan ignore
عرف اعمل(الرقم: عدد, الوارد: &مستلم<تدفق_تي_سي_بي>): فراغ {
    دع انتهى: متغير منطقي = خطأ;
    طالما (!انتهى) {
        طابق استقبل(الوارد) مع
        | نتيجة.نجح(التدفق) -> {
            اطبع_سطر(صل_ثلاثة_نصوص(&"العامل ", &عدد_إلى_نص(الرقم), &" استلم اتصالا."));
            عالج_الاتصال(التدفق);
        }
        | نتيجة.خطأ(_) -> { انتهى := صواب; };
    }
    اطبع_سطر(صل_ثلاثة_نصوص(&"العامل ", &عدد_إلى_نص(الرقم), &" توقف."));
}

عرف ابدأ_عاملا(الرقم: عدد, العمال: &متغير متجه مقبض_خيط): اختياري مرسل<تدفق_تي_سي_بي> {
    دع الوارد: مستلم<تدفق_تي_سي_بي> = مستلم_قناة<تدفق_تي_سي_بي>();
    دع الصادر: مرسل<تدفق_تي_سي_بي> = مرسل_لمستلم(&الوارد);
    طابق أطلق(دالة(): فراغ -> اعمل(الرقم, &الوارد)) مع
    | نتيجة.نجح(المقبض) -> {
        ألحق(*العمال, المقبض);
        أرجع اختياري.موجود(الصادر);
    }
    | نتيجة.خطأ(_) -> { أرجع اختياري.لا_شيء(); };
}
```

تصنع `ابدأ_عاملا` قناة، وتحتفظ بمرسلها لترجعه، وتبدأ خيطا يلتقط الـ closure الخاص به المستلم. ويمرر الـ closure `&الوارد` إلى
`اعمل`: فيبقى المستلم ملك الـ closure، ويُحرَّر حين ينتهي الخيط. وتنتظر `اعمل` على `استقبل` وتعالج كل تدفق تستلمه، وحين لا يبقى
للقناة مرسلون ترجع `استقبل` خطأ وتنتهي الحلقة. وتخزّن `ابدأ_عاملا` أيضا مقبض الخيط، لتنتظره لاحقا.

وتبدأ `الرئيسية` أربعة عمال، ثم ترسل كل اتصال مقبول إلى التالي:

<sub>القائمة 20-4: `الرئيسية` مع المجموعة. الملف: src/main.sn</sub>

```sultan ignore
عرف الرئيسية(): عدد {
    دع العنوان: عنوان_مقبس;
    طابق حلل_عنوان_مقبس(&"127.0.0.1:7878") مع
    | نتيجة.نجح(ع_م) -> { العنوان := ع_م; }
    | نتيجة.خطأ(_) -> { أرجع 1; };
    دع المستمع: مستمع_تي_سي_بي;
    طابق اربط_مستمع_تي_سي_بي(&العنوان, 128) مع
    | نتيجة.نجح(م) -> { المستمع := م; }
    | نتيجة.خطأ(الرمز) -> { أرجع الرمز; };

    دع العمال: متغير متجه مقبض_خيط = [];
    دع المرسلون: متغير متجه مرسل<تدفق_تي_سي_بي> = [];
    لكل (دع الرقم: متغير عدد = 0; الرقم < 4; الرقم := الرقم + 1) {
        طابق ابدأ_عاملا(الرقم, &متغير العمال) مع
        | اختياري.موجود(الصادر) -> { ألحق(المرسلون, الصادر); }
        | اختياري.لا_شيء -> { أرجع 1; };
    }

    دع التالي: متغير عدد = 0;
    طالما (صواب) {
        طابق اقبل_تي_سي_بي(&المستمع) مع
        | نتيجة.نجح(التدفق) -> {
            طابق أرسل(&المرسلون[التالي], التدفق) مع
            | نتيجة.نجح(_) -> { }
            | نتيجة.خطأ(_) -> { };
            التالي := (التالي + 1) % الطول(المرسلون);
        }
        | نتيجة.خطأ(_) -> { };
    }
    أرجع 0;
}
```

جرّب الطلبين من جديد:

```console
$ curl -s -o /dev/null http://127.0.0.1:7878/sleep &
$ time curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:7878/
200
```

هذه المرة يُجاب الطلب الثاني فورا، والعامل 0 ما زال نائما:

```text
العامل 0 استلم اتصالا.
GET /sleep HTTP/1.1
العامل 1 استلم اتصالا.
GET / HTTP/1.1
```

ولاحظ ما فحصه المترجم. تأخذ `عالج_الاتصال` ملكية التدفق، وينتقل التدفق من `الرئيسية` إلى عامل عبر القناة. فلو حاولت
`الرئيسية` استخدام تدفق بعد إرساله، أو حاول عامل أن يشاركه مع خيط آخر، لما ترجم البرنامج.
