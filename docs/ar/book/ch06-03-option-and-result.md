# `اختياري` و `نتيجة`

تعدادان مبنيان في اللغة، لأن كل برنامج تقريبا يحتاجهما. وقد استخدمت كليهما منذ الفصل الثاني.

## `اختياري`: قيمة قد تغيب

أسئلة كثيرة لا جواب لها في بعض الحالات: أول عدد زوجي في قائمة ليس فيها زوجي، أو المستخدم الذي لا يحمل أحد اسمه. وتجيب
لغات كثيرة بقيمة خاصة، `null`، تقوم مقام أي قيمة. ومشكلة `null` أن أي قيمة قد تكون هي سرا، ونسيان فحصها من أكثر الأخطاء
شيوعا.

وليس في السلطان `null`. فالقيمة التي قد تغيب نوعها `اختياري ن`، وهو تعداد له حالتان:

- `اختياري.موجود(القيمة)`: القيمة موجودة؛
- `اختياري.لا_شيء`: ليست موجودة.

```sultan
استورد المكتبة.دخ.اطبع_سطر;
استورد المكتبة.نصوص.أعداد;

عرف أول_زوجي(القيم: &متجه عدد): اختياري عدد {
    لكل (ليكن ع: متغير عدد = 0; ع < الطول(*القيم); ع := ع + 1) {
        إذا ((*القيم)[ع] % 2 == 0) {
            أرجع اختياري.موجود((*القيم)[ع]);
        };
    }
    أرجع اختياري.لا_شيء();
}

عرف بلغ(القيم: &متجه عدد): فراغ {
    طابق أول_زوجي(القيم) مع
    | اختياري.موجود(ن) -> { اطبع_سطر(عدد_إلى_نص(ن)); }
    | اختياري.لا_شيء -> { اطبع_سطر("لا عدد زوجي"); };
}

عرف الرئيسية(): عدد {
    ليكن أ: متجه عدد = [3, 5, 8, 9];
    ليكن ب: متجه عدد = [1, 7];
    بلغ(&أ);
    بلغ(&ب);
    أرجع 0;
}
```

```text
8
لا عدد زوجي
```

يخبر النوع `اختياري عدد` كل مستدعٍ بأنه قد لا يوجد جواب. و `اختياري عدد` ليس `عدد`، فلا يُستخدم العدد قبل إخراجه:

```sultan fail
عرف الرئيسية(): عدد {
    ليكن ربما: اختياري عدد = اختياري.موجود(5);
    ليكن ن: عدد = ربما + 1;
    أرجع ن;
}
```

```text
خطأ[SULTANC-TYPE-MISMATCH]: النوع الموجود ⁨`اختياري عدد`⁩ لا يطابق النوع المتوقع ⁨`عدد`⁩ — القيمة لا تطابق النوع المصرح به لوجهتها.
  --> main.sn:3:17..3:21
   |
 3 |     ليكن ن: عدد = ربما + 1;
   |                 ^^^^
   |
```

والطريق الوحيد إلى العدد `طابق`، ويجب أن تعالج `طابق` أيضا `اختياري.لا_شيء`. فلا يمكن أن "يُنسى فحص اللاشيء": فالفحص
مطلوب قبل الوصول إلى القيمة.

## `نتيجة`: جواب، أو سبب غيابه

تقول `اختياري` *هل* توجد قيمة. وحين يكون لغياب القيمة سبب يستحق الإبلاغ، استخدم `نتيجة`. ونوعها يذكر نوعين، نوع القيمة ونوع
الخطأ: `نتيجة ن, خ`. ولها حالتان:

- `نتيجة.نجح(القيمة)`: نجح الأمر، وهذه القيمة؛
- `نتيجة.خطأ(الخطأ)`: فشل، وهذا السبب.

```sultan
استورد المكتبة.دخ.اطبع_سطر;
استورد المكتبة.نصوص.أعداد;

عرف اقسم(أ: عدد, ب: عدد): نتيجة عدد, نص {
    إذا (ب == 0) {
        أرجع نتيجة.خطأ("قسمة على صفر");
    };
    أرجع نتيجة.نجح(أ / ب);
}

عرف اعرض(الحصيلة: نتيجة عدد, نص): فراغ {
    طابق الحصيلة مع
    | نتيجة.نجح(ن) -> { اطبع_سطر(عدد_إلى_نص(ن)); }
    | نتيجة.خطأ(رسالة_بلغة) -> { اطبع_سطر(رسالة_بلغة); };
}

عرف الرئيسية(): عدد {
    اعرض(اقسم(10, 2));
    اعرض(اقسم(1, 0));
    أرجع 0;
}
```

```text
5
قسمة على صفر
```

وكل من `اقرأ_السطر` و `حلل_طبيعي` و `وقت_نظام_نانو` من الفصل الثاني ترجع `نتيجة`، لأن كلا منها قد يفشل لسبب خارج سيطرة
البرنامج: أُغلقت المدخلات، أو النص ليس عددا، أو تعذرت قراءة الساعة. وتستخدم المكتبة القياسية `اختياري` حين يكون الغياب
عاديا، و `نتيجة` حين يكون فشلا.

ويبين [الفصل التاسع](ch09-00-error-handling.md) كيف تمرر `نتيجة` إلى المستدعي بـ `؟` بدلا من مطابقتها في كل مكان، وكيف
تصف الأخطاء بالنوع القياسي `فشل`.

## الخلاصة

- يصرّح `نوع الاسم = | أ | ب بنوع ن | …;` بتعداد، وقد تحمل الحالة قيمة واحدة بـ `بنوع`.
- تصنع `الاسم.أ()` قيمة، وتصنع `الاسم.ب(س)` قيمة تحمل `س`.
- تختار `طابق` الحالة وتسمي ما تحمله، والأنماط تتداخل وتفكك الصفوف والسجلات.
- كل حالة يجب أن تُعالَج، والأفضل سرد الحالات بدلا من `_`.
- `اختياري ن` قيمة أو لا شيء، و `نتيجة ن, خ` قيمة أو خطأ. وليس في السلطان `null`.
