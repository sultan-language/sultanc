# المراجع والاستعارة

انتهى القسم السابق بمشكلة: تمرير قيمة إلى دالة ينقلها، فيخسرها المستدعي. وأغلب الدوال تحتاج إلى النظر في القيمة فقط، ولها
يستطيع المستدعي أن يعير القيمة بدلا من أن يعطيها.

## المراجع

*المرجع* (reference) يشير إلى قيمة يملكها غيره. ونوعه يُكتب `&ن`، ويُصنع مرجع إلى متغير بـ `&الاسم`:

```sultan
استورد المكتبة.دخ.اطبع_سطر;
استورد المكتبة.نصوص.أعداد;

عرف عد(القيم: &متجه عدد): عدد {
    أرجع الطول(*القيم);
}

عرف الرئيسية(): عدد {
    دع الأعداد: متجه عدد = [1, 2, 3];
    دع ن: عدد = عد(&الأعداد);
    اطبع_سطر(عدد_إلى_نص(ن + الطول(الأعداد)));
    أرجع 0;
}
```

```text
6
```

تعير `عد(&الأعداد)` المتجه: تأخذ `عد` مرجعا، وتبقى الملكية لـ `الرئيسية`. وحين ترجع `عد` ينتهي مرجعها، ولا ينتهي المتجه،
لأن المرجع لم يملكه قط. فتستطيع `الرئيسية` أن تستخدم `الأعداد` بعد ذلك.

وداخل `عد`، `*القيم` هو المتجه الذي يشير إليه المرجع. فـ `*` تتبع المرجع إلى قيمته، ويسمى هذا *فك المرجع* (dereferencing).

وإعارة قيمة عبر مرجع تسمى *الاستعارة* (borrowing). وكما في الحياة، ما تستعيره تعيده، ولا تعطيه لغيرك.

وقد استخدمت المراجع منذ الفصل الثاني: `قص_النص(&السطر)` و `صل_نصين(&"خمّنت: ", &التخمين)`. فدوال النصوص تأخذ `&نص` لأنها
تقرأ النص فقط.

## المراجع القابلة للتغيير

المرجع `&ن` العادي يسمح للمستعير بالقراءة لا بالتغيير. ولتسمح لدالة بتغيير قيمة تستعيرها، أعرها بـ `&متغير`. فالنوع
`&متغير ن`، ويكتب الاستدعاء `&متغير الاسم`، ويجب أن يكون المالك نفسه `متغير`:

```sultan
استورد المكتبة.دخ.اطبع_سطر;
استورد المكتبة.نصوص.أعداد;

عرف أضف_غرضا(السلة: &متغير متجه نص, الغرض: &نص): فراغ {
    ألحق(*السلة, استنسخ(الغرض));
}

عرف الرئيسية(): عدد {
    دع السلة: متغير متجه نص = [];
    أضف_غرضا(&متغير السلة, &"خبز");
    أضف_غرضا(&متغير السلة, &"حليب");
    اطبع_سطر(عدد_إلى_نص(الطول(السلة)));
    أرجع 0;
}
```

```text
2
```

تضيف `ألحق` عنصرا في آخر المتجه. وتعطي `استنسخ(الغرض)` السلة نسختها الخاصة من النص، لأن `الغرض` مستعار فقط: فلا تحتفظ السلة
بقيمة يملكها غيرها. ويغطي القسم التالي `استنسخ`.

## قواعد المراجع

يتحقق المترجم من قاعدتين لكل مرجع.

**الأولى: المرجع القابل للتغيير يمنع أي مرجع آخر إلى القيمة نفسها.** فما دام جزء من البرنامج قد يغيّر قيمة، لا يجوز لجزء
آخر أن يقرأها:

```sultan fail
عرف كلاهما(الهدف: &متغير متجه عدد, المصدر: &متجه عدد): فراغ {
    ألحق(*الهدف, الطول(*المصدر));
}

عرف الرئيسية(): عدد {
    دع القيم: متغير متجه عدد = [1];
    كلاهما(&متغير القيم, &القيم);
    أرجع 0;
}
```

```text
خطأ[SULTANC-BORROW-CONFLICT]: تعارض استعارة — القيمة ذات الاستعارة المتعارضة هي ⁨`القيم`⁩. القيمة مستعارة للقراءة، لذا لا يمكن استعارتها استعارة متغيرة.
  --> main.sn:6:5..6:36
   |
 6 |     دع القيم: متغير متجه عدد = [1];
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   |
```

لماذا يُمنع هذا؟ تضيف `كلاهما` إلى `الهدف` وهي تقرأ `المصدر`. فإن كانا المتجه نفسه، فقد تنقل الإضافة محتوى المتجه إلى مكان
أكبر في الذاكرة، فيشير `المصدر` إلى ذاكرة أُعيدت. وهذا النوع من الأخطاء، ويسمى *سباق البيانات* (data race) حين تشارك فيه
الخيوط، صعب الاكتشاف لأنه يعتمد على التوقيت والأحجام. والقاعدة تجعله مستحيلا.

ويجوز وجود أي عدد من المراجع للقراءة فقط في الوقت نفسه، فالقراءة لا تزعج القرّاء الآخرين.

**الثانية: لا يعيش المرجع أطول من القيمة التي يشير إليها.** هنا ترجع دالة مرجعا إلى متغيرها المحلي:

```sultan fail
عرف معلق(): &نص {
    دع ن1: نص = "أهلا";
    أرجع &ن1;
}

عرف الرئيسية(): عدد {
    دع ر: &نص = معلق();
    أرجع 0;
}
```

```text
خطأ[SULTANC-BORROW-REFERENCE-ESCAPE]: المرجع يهرب من نطاق صلاحيته — المرجع الخارج عن نطاق صلاحيته هو ⁨`ن1`⁩. يبقى مرجع بعد انتهاء القيمة التي يشير إليها.
  --> main.sn:2:5..2:24
   |
 2 |     دع ن1: نص = "أهلا";
   |     ^^^^^^^^^^^^^^^^^^^
   |
```

يُحرَّر `ن1` حين ترجع `معلق`، فيشير المرجع إلى ذاكرة محررة: مرجع *معلّق* (dangling). ويرفضه المترجم. والإصلاح أن ترجع
`نص` نفسه، فينتقل إلى المستدعي.

## لا تنقل من شيء مستعار

يعير المرجع القيمة ولا يعطيها. فلا يجوز أن تأخذ قيمة مالكة من شيء استعرته فقط:

```sultan fail
عرف الأول(الأسماء: &متجه نص): نص {
    أرجع (*الأسماء)[0];
}

عرف الرئيسية(): عدد {
    دع الأسماء: متجه نص = ["هدى"];
    دع الأول_منها: نص = الأول(&الأسماء);
    أرجع 0;
}
```

```text
خطأ[SULTANC-OWNERSHIP-MOVE-OUT-OF-REFERENCE]: لا يجوز نقل قيمة مملوكة من تخزين مستعار — القيمة المنقولة من تخزين مستعار هي ⁨`الأسماء`⁩. جرت محاولة نقل قيمة مملوكة من تخزين مستعار.
  --> main.sn:2:10..2:23
   |
 2 |     أرجع (*الأسماء)[0];
   |          ^^^^^^^^^^^^^
   |
```

إرجاع `(*الأسماء)[0]` ينقل النص الأول من متجه المستدعي، فيترك فيه ثغرة. أرجع نسخة بدلا من ذلك:

```sultan
استورد المكتبة.دخ.اطبع_سطر;

عرف الأول(الأسماء: &متجه نص): نص {
    أرجع استنسخ(&(*الأسماء)[0]);
}

عرف الرئيسية(): عدد {
    دع الأسماء: متجه نص = ["هدى", "سارة"];
    دع الأول_منها: نص = الأول(&الأسماء);
    اطبع_سطر(الأول_منها);
    اطبع_سطر(الأسماء[1]);
    أرجع 0;
}
```

```text
هدى
سارة
```

## طباعة قيمة ما زلت تحتاجها

وجد سؤال `اطبع_سطر` في القسم السابق جوابه. تقرأ `اطبع_سطر` نصها فقط، فهي تأخذ `&نص` مثل دوال النصوص. وتستطيع أن تعيرها
النص بـ `&` كما تعيره لأي منها. ولأن النص يُمرَّر للقراءة كثيرا، يعيره السلطان عنك: فالـ `نص` المُمرَّر حيث تنتظر الدالة
`&نص` يُستعار للاستدعاء، كأنك كتبت `&`:

```sultan
استورد المكتبة.دخ.اطبع_سطر;

عرف الرئيسية(): عدد {
    دع التحية: نص = "أهلا";
    اطبع_سطر(&التحية);
    اطبع_سطر(التحية);
    اطبع_سطر(التحية);
    أرجع 0;
}
```

```text
أهلا
أهلا
أهلا
```

لا ينقل أي من الاستدعاءات الثلاثة `التحية`، فتبقى ملك `الرئيسية` بعدها. ولهذا طبعت `اطبع_سطر(الأسماء[1])` أعلاه العنصر
دون أن تأخذه من المتجه.

وهذه القاعدة للنصوص وحدها. فالمتجه والسجل وأي قيمة أخرى تُمرَّر إلى معامل `&` ما زالت تحتاج `&` مكتوبة.

## الخلاصة

- يستعير `&ن` قيمة لقراءتها، ويستعيرها `&متغير ن` لتغييرها. وتصل `*` إلى القيمة.
- لا يوجد مرجع قابل للتغيير مع أي مرجع آخر إلى القيمة نفسها.
- لا يعيش المرجع أطول من قيمته.
- لا شيء يُنقل من قيمة مستعارة، فأرجع نسخة أو خزّنها.
- الـ `نص` المُمرَّر حيث يُنتظر `&نص` يُستعار للاستدعاء، وغيره من القيم يحتاج `&`.
