# Installation

SultanC is built from source. The compiler is written in SultanC, so the build starts from a small seed
that is part of the repository and uses it to build the real compiler. You do not need an existing
SultanC compiler.

> **Command line notation.** Lines in this book that start with `$` are commands you type in a
> terminal; do not type the `$`. Lines without it are what the command prints.

There are two routes. Which one you use depends on your system.

| Your system | Route | What you need |
| --- | --- | --- |
| Linux on x86_64 | WebAssembly seed | Git, a C compiler |
| macOS on Apple silicon (M1 and later) | WebAssembly seed | Git, a C compiler |
| Windows, Linux on ARM, macOS on Intel, FreeBSD and others | the C Stage0 chain with LLVM | Git (the full history), a C compiler, LLVM 19 to 23 |

The difference is the backend: the part of the compiler that produces machine code. SultanC has its
own backend, called Native, for x86_64 Linux and Apple silicon macOS. On every other system the
compiler produces code through LLVM, so LLVM has to be installed before you build.

## Linux (x86_64)

Install the tools with your distribution's package manager:

```console
$ sudo apt install git build-essential     # Debian, Ubuntu
$ sudo dnf install git gcc make            # Fedora
$ sudo pacman -S git base-devel            # Arch
```

Then build:

```console
$ git clone https://github.com/sultan-language/sultanc.git
$ cd sultanc
$ ./build.sh
build: translating the seed to C (bootstrap-wasm/seed/sultanc.wasm.zst)
build: compiling C (11 files)
build: seed compiler: build/bootstrap/seed/sultanc-stage1
build: building the build driver (tools/build)
build: building the compiler from compiler/ with the seed compiler
build: compiler: build/sultanc
```

The last line names the result: the compiler is `build/sultanc`. The first build starts from the seed;
every later `./build.sh` takes one step from the compiler you already have, and does nothing when the
compiler's sources have not changed. `./build.sh --verbose` also shows each command it runs.

Without a shell, one C file does the same build, with only the C compiler, and ends with the same
`build/sultanc`:

```console
$ cc -o build-bootstrap bootstrap-wasm/bootstrap.c && ./build-bootstrap
```

To check the compiler, `./build.sh verify` builds it, builds it again with itself, and requires the two
to be identical (`./build-bootstrap --verify` without a shell). The commands for maintainers
(`./build.sh seed-update`, `seed-check` and `chain`) are in [Bootstrap](../internals/bootstrap.md).

## macOS (Apple silicon)

The C compiler comes with Apple's command line tools:

```console
$ xcode-select --install
```

Then build with the same commands as on Linux:

```console
$ git clone https://github.com/sultan-language/sultanc.git
$ cd sultanc
$ ./build.sh
```

## Windows, and every other system

These systems have no Native backend. `./build.sh` (or `build-bootstrap`, which needs only a C compiler,
on Windows too) still ends with `build/sultanc`, but there it is the seed compiler: it runs on your
system and generates code only for x86_64-linux, arm64-darwin and wasm32-wasi, and the build says so in
one line. A compiler for these systems themselves is generated by LLVM. The frozen C Stage0 in the
repository builds one: it compiles the compiler of a pinned commit, which builds the current compiler.
Install Git, a C compiler and LLVM 19 to 23, clone the whole history, and run the chain:

```console
$ git clone https://github.com/sultan-language/sultanc.git
$ cd sultanc
$ sh bootstrap/chain.sh
$ cp build/chain/sultanc-a build/sultanc
```

The chain finds LLVM through `llvm-config`. If yours is somewhere else, name it with
`LLVM_CONFIG=/path/to/llvm-config sh bootstrap/chain.sh`.

On Windows, run `bootstrap/chain.ps1` from a Visual Studio developer PowerShell, with `LLVM_SDK` naming an
LLVM build that holds `include\`, `lib\LLVM-C.lib` and `bin\LLVM-C.dll`. The LLVM that the official installer
ships does not include every target or the LLVM-C library, so LLVM has to be built from its source once: the
`llvm-sdk` job of `.github/ci/windows.ps1` does exactly that. The compiler is `build\chain\sultanc-a.exe`;
keep `LLVM-C.dll` beside it.

Alternatively, on Linux x86_64 or Apple silicon, `./build.sh --enable-llvm` followed by
`./build.sh --target=x86_64-windows-msvc --backend=llvm --with=build/sultanc` builds a compiler for another
system (here Windows, into `build/cross/`). It contains only the Native backend, so it checks and runs
programs there but generates code only for Native targets.

## The result

A build takes a few minutes. When it finishes, the compiler is `build/sultanc`. Check that it runs:

```console
$ build/sultanc --lang=en version
SultanC development
backends: native
```

`--lang=en` asks for English; without it, the compiler answers in Arabic. The last line lists the backends your compiler contains: `native`, `llvm`, or both.

## Installing `sultanc` and Supax

Supax is SultanC's package manager. It creates projects, fetches the packages they depend on, and
builds, runs and tests them. Its installer also puts `sultanc` and the standard library on your
`PATH`. Clone Supax next to the compiler and run the installer, giving it the compiler's folder:

```console
$ cd ..
$ git clone https://github.com/sultan-language/supax.git
$ cd supax
$ tools/install.sh ../sultanc
```

On Windows, run `tools\install.ps1` instead. Both put `sultanc`, `supax` and the standard library in
the folder `.supax` in your home folder, and add `.supax/bin` to your `PATH`. Open a new terminal and
check:

```console
$ sultanc --lang=en version
$ supax --lang=en --help
```

## Trying SultanC without installing

The [playground](https://sultan-language.github.io/playground/) compiles and runs SultanC in your
browser. It is enough for the programs in the first chapters of this book.
