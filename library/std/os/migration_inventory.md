# OS migration inventory — post-runtime deletion

The obsolete `library/std/os/runtime.sn` was deleted from this checkpoint.
The original 59 declarations remain available only in the authoritative
input archive. The table inventories real native platform source, **not**
new declarations or assumed executable support. Existing `std.os` and STD
consumer calls require native providers and target-specific selection; **the deletion is
not equivalent to a completed migration**.

No libc, alternate ABI shim, host fallback, or machine-code blob is supplied.

## Darwin (macOS arm64) provider (2026-10-17)

- New canonical Darwin providers under `os/platform/unix/apple/darwin/`: `file_descriptors.sn` (open/creat/read/write/close/lseek/fsync/fchmod/rename/unlink/stat/getcwd, errno via `__error`), `directories.sn` (opendir/readdir/closedir/mkdir/rmdir), `process_control.sn` (posix_spawn with `POSIX_SPAWN_CLOEXEC_DEFAULT` plus inherited 0/1/2, waitpid with EINTR retry, `_exit`) and `error_translation.sn` (Darwin errno values). They call libSystem, the supported Darwin system-call interface (the raw Darwin syscall ABI is private), in the same role as the Win32 provider's kernel32 declarations. Variadic entry points are called with fixed arguments only.
- `os.file`, `os.directory`, `os.io`, `os.environment`, `os.process`, `os.error_translation` and `process.child` gained `الهدف.المنصة == «macos»` selections. `os.arguments` and the environment lookup use the shared Unix startup contract.
- The startup reader moved from `os/platform/unix/linux/startup.sn` to `os/platform/unix/process_startup.sn` (`*_إقلاع_يونكس`): the `sultanc.bootstrap.*` argc/argv/envp data symbols are defined identically for Linux and Darwin executables.
- Verification: Stage0 compiles the full compiler closure for `arm64-darwin`; the Linux-hosted Stage1 and Stage2 cross-build a Mach-O arm64 compiler deterministically. Execution on macOS: NOT RUN here (no macOS host).

## Current native additions (source-only, no execution claim)

- Linux process/error-channel ownership: `pipe2(O_CLOEXEC)` descriptors are elevated out of the standard-stream range with the existing Linux `fcntl` syscall before `clone`, so a parent with closed fd 0/1/2 does not accidentally hand its private error channel to the child as stdin/stdout/stderr. All owned duplicates and originals are closed on errors. Linux sockets created or accepted by the canonical provider now set `SOCK_CLOEXEC` atomically, preventing unintended socket inheritance. Kernel socket sends also set `MSG_NOSIGNAL`, preserving `EPIPE` instead of terminating the process with `SIGPIPE`. This has not been compiled or executed.

- Linux resolver: `os.socket.حل_اسم_مضيف_النظام` selects the native Linux source provider. The provider reads bounded `/etc/hosts` and `/etc/resolv.conf` snapshots, supports up to three configured IPv4/IPv6 nameservers, `search` / `domain` / `ndots`, A/AAAA records, compressed owner names, bounded in-response and follow-up CNAME chains, and DNS-over-TCP framing for truncated UDP answers. Query IDs come from kernel `getrandom`; sockets and files have explicit ownership/cleanup. The TCP connection now uses SOCK_NONBLOCK with ppoll(SO_ERROR) and a two-second deadline. Remaining unsupported resolver policy includes EDNS0, IDNA and some advanced retry rules; no runtime verification has been performed. No libc, public DNS fallback or separate network provider exists.
- Linux temporary paths: a pure, connected TMPDIR selection function now validates a supplied startup value. No source of live Linux `environ` was present in this authoritative checkpoint, so the live `اقرأ_دليل_مؤقت_النظام` cannot yet be provided.
- Windows memory: Win32 pointer-backed VirtualAlloc resources have canonical typed `std.os.virtual_memory` operations with native errors. No numeric pointer adapter or copied allocator implementation was created.
- Linux process creation: `process_control.sn` now implements an explicit-environment `شغل_طفلا_لينكس_ببيئة` source path for x86-64/AArch64: bounded owned executable/argv/envp storage, `clone(SIGCHLD)` without shared VM/file tables, `close_range` descriptor isolation, an `O_CLOEXEC` pipe carrying child `execve` errno, parent-side EOF/validated errno-record handling, close-error cancellation and child reaping, and EINTR-aware `waitid`. The canonical `os.process.شغل_عملية_نظام_ببيئة` exposes this typed source path. Linux `close_range` requires kernel 5.9+; ENOSYS is an explicit failure, not a descriptor-leaking fallback. **The preexisting two-argument `شغل_عملية_نظام` cannot inherit the actual environment until the compiler supplies typed startup `envp` access**. No child code allocates after clone. Semantic compilation and runtime behavior NOT RUN.

## Process lifecycle and native resource corrections (2026-10-12)

- **Linux x86-64/AArch64:** The canonical explicit-environment spawn provider now treats failures to close either parent error-channel descriptor as failures of ownership transfer, cancels/reaps the child on channel failure, and rejects malformed child-error records as protocol errors rather than fabricating a native `errno`. A successful `execve` is still inferred from `O_CLOEXEC` pipe EOF, while a valid error record preserves the kernel `errno`. Child waiting remains EINTR-aware, validates SIGCHLD/PID/status records, and distinguishes ordinary exit from signal termination. Linux `close_range` still requires kernel 5.9+; no alternative descriptor-isolation policy was introduced.
- **Linux file output:** Complete executable-byte writes now retry an interrupted `write` without discarding completed partial transfers. Descriptor closure still occurs on every terminal write failure; `close` itself is never retried after EINTR because Linux consumes that descriptor.
- **Windows:** The existing Win32 process provider now attempts closure of both independently owned PROCESS and THREAD handles, preserving its first failure. The portable process API does not mark a HANDLE released when its close fails; a failed thread-handle handoff attempts child termination, bounded waiting, and cleanup before returning the original error. These are native Win32 interfaces, not libc.
- **Argument contract:** `os.arguments` begins with a target-neutral index validator and retains guarded Windows-specific source declarations. The Linux data symbols `sultanc.bootstrap.argc`, `sultanc.bootstrap.argv`, and `sultanc.bootstrap.envp` remain **linker data symbols**, not callable functions. The inspected checkpoint does not establish their typed SultanC source-access contract; no alternative process-state owner was added.
- **Targets/verification:** Changes are in canonical providers for Linux x86-64/AArch64 and Windows 64-bit targets only. Darwin, FreeBSD, Android, WASI, freestanding, and specialist targets are unchanged. **Native compilation, linking, execution, and all tests: NOT RUN**. All 59 historical entries below remain source/integration classifications, not runtime PASS claims.

## Independent native-source corrections (2026-10-12 continuation)

- **Linux owned file descriptors:** `os.file` opens reading/writing handles with
  `O_CLOEXEC`; native executable-byte output and optional procfs auxiliary
  vector reads likewise use `O_CLOEXEC`. This prevents those independently
  opened descriptors from accidentally surviving `execve`. It does not alter
  the deliberate child descriptor-isolation policy (`close_range`, Linux 5.9+)
  or add a fallback for older kernels.
- **Linux DNS:** the existing connected native resolver fills the two-byte
  query identifier across partial `getrandom` returns and retries `EINTR`,
  retaining non-interruption kernel error identities and rejecting zero
  progress. It does not use fixed transaction IDs or libc services.
- **Startup-data boundary:** no supported typed external-data declaration or
  load of `sultanc.bootstrap.argc`, `sultanc.bootstrap.argv`, or
  `sultanc.bootstrap.envp` exists in the inspected supplied compiler. The
  two-argument inherited-environment spawn, Linux argument retrieval and live
  environment/TMPDIR access therefore remain unconnected. These are not
  kernel syscalls; additional `std.os` code must use the actual compiler
  source contract once the compiler owner supplies it.
- **Native coverage:** no newly claimed Darwin, FreeBSD, Android, WASI or
  specialized target execution support. The 59 statuses below are unchanged
  except for the corrected file ownership and resolver random-input behavior.
  Compilation, linkage, tests and execution have not been performed.

## Legacy 59-service migration status — source inventory

The 59 names below are **historical identifiers only**. They are not
redeclared, re-exported, or implemented as compatibility symbols.
`runtime.sn` is absent in the supplied merged checkpoint and remains absent.

**Scope of the Linux implementation:** direct calls through the compiler’s
`بدائي_نداء_نواة_خام` primitive, limited by its existing contract to
Linux x86-64 and AArch64 with 64-bit pointers. Architecture syscall numbers
are provided by `numbers_x86_64.sn` or `numbers_asm_generic_64.sn`, respectively;
the source selector chooses the table using the selected target.
The kernel providers accept selected syscall numbers as arguments; they do
not detect the host or choose their own target. A supplied number and a
callable primitive establish native source operations; only the individually
marked rows below have portable-API integration. None proves executable correctness.

**Common verification:** source-only inspection. Compiler driver/interpreter
consumers remain outside writable scope; build, linking, tests and execution
NOT RUN. All **20 authorized STD consumer files** have had their obsolete `os.runtime`
imports and `تشغيل_*` call sites removed. This is **not** full functional
integration: Linux startup arguments/environment, automatic environment inheritance for the two-argument spawn API, full resolver behavior
(EDNS0, IDNA and certain resolver-policy details), and Windows numeric STD memory adapters still lack
complete native providers. Linux DNS is connected through UDP/TCP paths.
Windows source providers retain separate Win32/Winsock ABI identities.
Compile-time `الهدف.المنصة` / `الهدف.المعمارية` guards select implemented
Linux x86-64/AArch64 or Windows operations in the portable modules; this is
the canonical frontend's selection facility, **not** a new STD target registry. Android, other Linux architectures,
Darwin/FreeBSD, WASI, browser and special targets are **not** covered by the
new Linux primitive; the target-aware contracts must be handled separately.

## Exact read-only compiler handoff

- `compiler/driver/process_driver.sn` **already imports `std.os.file` and `std.os.error`** and calls **`اكتب_بايتات_تنفيذية_للنظام`** via `اكتب_بايتات_تنفيذية_عملية`. No legacy `os.runtime` import or additional replacement is required in this checkpoint. Runtime behavior remains unverified.
- `compiler/interpreter/execution/primitives.sn` **does not import `std.os.runtime`**. It owns interpreter primitive evaluation, not an independent OS implementation. No legacy file/directory/stream ABI call is present in that file to migrate in this checkpoint. Interpreter execution of target-specific syscalls and safe pointer semantics belongs to the read-only interpreter/compiler owner and remains unverified.
- Compiler startup/ABI prerequisite: the authoritative compiler publishes the **data symbols** `sultanc.bootstrap.argc` (u64 count), `sultanc.bootstrap.argv` (pointer to original argv vector), and `sultanc.bootstrap.envp` (pointer to original environment vector). Static inspection did **not** find a SultanC source syntax / semantic-lowering contract for declaring, resolving, loading and dereferencing external **data** symbols. Agent 1 must expose data-symbol imports as typed read-only process-lifetime data (not functions) with target-aware symbol names, pointer-width/alignment rules, NULL vector handling and safe borrow/copy semantics. `os.arguments.{عدد_وسائط_النظام,وسيطة_النظام}` and `os.environment.{طول_متغير_بيئة_نظام,اقرأ_متغير_بيئة_نظام}` can then copy bounded startup bytes into owned values; `TMPDIR` selection consumes the resulting environment value. A Linux kernel syscall cannot retrieve argv/environ. Explicit-env clone+execve source is now implemented inside std.os with child error-channel transfer and PID ownership. The *two-argument* `شغل_عملية_نظام` and its `std.process.child` consumer still require a typed copy of the process's startup environment to inherit it. Generic syscall lowering for additional Linux architectures and proof that the child-side primitive is safe across both compiler backends remain compiler-owner dependencies. No build/test/execution verification was performed.
- Linux DNS now uses one canonical connected resolver with `/etc/hosts`, resolver `search`/`domain`/`ndots` configuration, up to three configured IPv4/IPv6 nameservers, kernel `getrandom`, checked RFC 1035 compression and CNAME records (including bounded follow-up queries), UDP retries, and DNS-over-TCP on truncated replies. TCP connects now use nonblocking ppoll/SO_ERROR with a two-second deadline. Remaining: EDNS0, IDNA, and some resolver error/retry policies; runtime NOT RUN. Windows continues using native `GetAddrInfoW`.
- Linux `TMPDIR` selection/validation is defined by `os.platform.unix.linux.temporary_directory.اختر_دليل_مؤقت_لينكس`, exposed through `os.environment.اختر_دليل_مؤقت_نظام_من_البيئة`. The process startup ABI must supply the actual environment value before this can serve the live temp-directory contract; there is deliberately no unconditional `/tmp` fallback.
- Linux child execution uses raw `clone(SIGCHLD)` with a NULL stack and without CLONE_VM; the raw argument convention differs between x86-64 and AArch64, but all architecture-dependent trailing arguments are zero. `close_range` requires Linux 5.9+. Primary ABI references: https://man7.org/linux/man-pages/man2/clone.2.html and https://man7.org/linux/man-pages/man2/close_range.2.html. Runtime correctness remains unverified.
- Target selection must exclude inactive platform definitions from semantic indexing; no std-side target registry or runtime host fallback is introduced. The raw syscall primitive is proven by source contracts only for Linux x86-64 and AArch64. Other Linux ABI lowering, Android runtime semantics, and Win32/Winsock external-symbol resolution remain compiler-owned prerequisites.
- Windows typed virtual memory is connected via the canonical `os.virtual_memory` exports `احجز_منطقة_ذاكرة_نظام_ويندوز`, `حرر_منطقة_ذاكرة_نظام_ويندوز`, `احم_منطقة_ذاكرة_نظام_ويندوز`, `اقفل_منطقة_ذاكرة_نظام_ويندوز`, `الغ_قفل_منطقة_ذاكرة_نظام_ويندوز`, and `استبق_منطقة_ذاكرة_نظام_ويندوز`. Ownership and native error identity stay with `os.platform.windows.win32.virtual_memory`. The read-only `std.memory.system` numeric API still needs a verified pointer-to-word representation and lifetime migration from its owner; no guessed cast has been added.

## WASI provider and program lookup (2026-10-19)

- WASI preview 1 provider (`os.platform.wasi.preview1`): `process_control` (proc_exit), `file_descriptors` (fd_read/fd_write/fd_close/fd_seek/fd_sync, path_open, path_filestat_get, path_rename, path_unlink_file, path_create_directory, path_remove_directory, fd_readdir, and preopened-directory resolution through fd_prestat_get/fd_prestat_dir_name, choosing the longest containing preopen; relative paths use a "." preopen, else "/"), `process_startup` (args_* and environ_*), `clocks` (clock_time_get, poll_oneoff sleep) and `error_translation` (WASI errno numbering). `os.process`, `os.io`, `os.arguments`, `os.environment`, `os.file`, `os.directory`, `os.clock` and `os.error_translation` select them for `الهدف.المنصة == «wasi»`. WASI has no working-directory call (`اقرأ_دليل_عمل_النظام` reports "/", wasi-libc's convention) and no process creation. The import module `wasi_snapshot_preview1` is a target fact (`compiler/backend/target/runtime_symbol_query_context.sn`, `وحدة_استيراد_نظام_للهدف`). No C library is linked: on wasm32 the compiler storage services (allocate/reallocate/free) are implemented by std in `os/allocation.sn` over the linear-memory compiler intrinsics, bound in MSIR as the program's allocation providers and called by both the native wasm32 path and the LLVM provider. Verified under Node 22 WASI and wasmtime: streams, arguments, environment, file write/read/size/rename/unlink, mkdir/readdir/rmdir, relative paths, clocks and sleep.
- WASI startup strings follow the host's pointer table (`process_startup.sn`, `اقرأ_سلاسل_جدول_واسي`): entry i is the NUL-terminated string at pointer i, read from linear memory and bounded by the memory size and the host-reported buffer size (a violation reports `نطاق_غير_صالح`). Previously the buffer was split at NULs in order, which assumed the host packs the strings contiguously in table order. Verified under wasmtime for native and LLVM wasm32 outputs.
- The wasm32 allocator (`os/allocation.sn`) uses 334 size classes: 256 classes of 16-byte steps up to 4 KiB, then four quarter steps per power of two (at most 25% rounding) instead of rounding large requests to the next power of two, and `أعد_تخصيص_ذاكرة_التشغيل` grows the block at the end of the heap in place. Freed blocks are still reused per class. Previously large vectors that grow repeatedly wasted up to half of each block, which pushed the WASI-hosted compiler over the 4 GiB wasm32 limit.
- Program lookup for spawning now follows execvp/posix_spawnp: a spelling containing `/` is used as given; a bare name is searched in the parent's startup `PATH` in order (an empty element names the current directory). Linux builds every candidate before `clone` and the child tries them with `execve` (ENOENT/ENOTDIR continue, EACCES is reported if nothing else runs). A missing `PATH` is ENOENT; no default search list is invented. Darwin uses `posix_spawnp`. Previously a bare tool name (for example `wasm-ld`, `ld.lld`) always failed with ENOENT on both systems.
